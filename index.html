Planning by keeping a stack of things to do

A plan is a sequence of actions that takes the world from an initial state to a goal state. Goal stack planning, used in the STRIPS planner, builds that sequence by working on one goal at a time: it always looks at whatever is on top of a stack.

The world state

A list of true facts such as ON(B,A) and ARMEMPTY. Every operator changes this list.

The goal stack

Holds goals and operators. The planner pops the top item and either solves it, breaks it up, or applies it.

The plan

The operators actually applied, in order. When the stack is empty, this list is the answer.

Because subgoals are solved one after another, this is a linear planner.

The blocks world and its four operators

Facts used: ON(x,y) ONTABLE(x) CLEAR(x) HOLDING(x) ARMEMPTY

OperatorPreconditionDelete listAdd list
STACK(x,y)CLEAR(y) ∧ HOLDING(x)CLEAR(y), HOLDING(x)ARMEMPTY, ON(x,y)
UNSTACK(x,y)ON(x,y) ∧ CLEAR(x) ∧ ARMEMPTYON(x,y), ARMEMPTYHOLDING(x), CLEAR(y)

PUTDOWN(x)HOLDING(x)HOLDING(x)ONTABLE(x), ARMEMPTY

An operator can only run when its precondition holds. After it runs, remove the delete list from the state and add the add list.

What the planner does with the top of the stack

Start by pushing the goal. Repeat until the stack is empty:

Compound goalPush it back, then push each of its parts above it in any order. It is checked again once its parts are done.
Single goal, already truePop it and move on.
Single goal, not trueReplace it with an operator whose add list contains it, then push that operator's preconditions above the operator.
OperatorPop it, update the state with its delete and add lists, and append it to the plan.

Goal: ON(C,A) ∧ ON(B,D) ∧ ARMEMPTY

Click or press the right arrow to step through.

1Push the goal and its parts. Top is ON(C,A), so plan STACK(C,A), which needs CLEAR(A) and HOLDING(C).
2CLEAR(A) is false because B is on A. Use UNSTACK(B,A). Its preconditions hold, so apply it. The arm now holds B.
3HOLDING(C) needs PICKUP(C), which needs ARMEMPTY. The arm is full, so apply PUTDOWN(B), then PICKUP(C).
4Both preconditions of STACK(C,A) are true, so apply it. ON(C,A) is done.
5Next part, ON(B,D): apply PICKUP(B) and then STACK(B,D). The compound goal is now satisfied and the stack is empty.

Where goal stack planning falls short

What works

  • Simple to implement and easy to trace by hand.
  • Every operator in the plan is there because a goal needed it.
  • Works well when subgoals do not interfere.

Plans may be longer than needed

The plan above has 6 steps. Stacking B on D straight after unstacking it gives 4: UNSTACK(B,A), STACK(B,D), PICKUP(C), STACK(C,A).

Sussman anomaly

Start
A
C
B
Goal
C
B
A

Goal: ON(A,B) ∧ ON(B,C). Whichever goal is done first, finishing the other undoes it.

The fix is to interleave subgoals instead of finishing them one at a time. That leads to plan space and hierarchical planning, the next topics in this chapter.

Summary and references

Takeaways

  • One stack holds goals and operators; the top item decides the next move.
  • Unsatisfied goals become operators plus their preconditions.
  • Applied operators form the plan.
  • Linear ordering causes goal interaction problems such as the Sussman anomaly.
